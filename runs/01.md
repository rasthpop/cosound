Phase plans (skills/phases/)

skills/phases/README.md has the dependency graph, the mapping from base.md milestones M1–M7 to phases, and a table showing which task covers each item in the plan's Definition of Done.

- Functional track, P00–P10: foundation → domain model → Discogs/FMA ingestion → CLAP embeddings → hybrid retrieval → evaluation harness → agents A/B/C → spatial map (can run in parallel once embeddings exist) → API → frontend data layer → final evaluation and docs.
- UI track, U00–U05: plan intake → design tokens/theme → views → deck.gl map → screens → quality and isolation proof. These are provisional placeholders; U00.T01 is marked blocked until the UI/UX plan arrives.
- Every task lists the skills to load, its dependencies, the files it should touch, the steps, testable "done when" criteria, and a status checkbox.

Keeping the UI separate from the functional system

- The boundary: the UI only sees the four hooks and the TypeScript types generated from the API's OpenAPI schema. The functional track owns frontend/src/{api,hooks,mocks}; the UI track owns theme/, components/ and pages/.
- UI without a backend: the UI can be built against mock API responses produced from the backend's own schema examples (P08.T07, P09.T02), so it never needs a running backend.
- Missing data: if the UI needs data the API doesn't provide, it adds a request task to P08/P09 rather than working around it in the views.
- Proof at the end: U05.T05 swaps out the whole visual layer and checks that every functional test still passes untouched.
