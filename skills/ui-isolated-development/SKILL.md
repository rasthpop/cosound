# UI Isolated Development

Goal: the UI track can build and verify everything against the **contract** (`api-contracts`) without running Python, CLAP, or UMAP — and the functional track can verify hooks without any visual components.

## 1. Fixtures & mocks (`frontend/src/mocks/`, owned by functional track P09)

```
mocks/
├── fixtures/                  # generated from backend DTO examples (scripts/export_fixtures.py)
│   ├── search_ok.json  search_empty.json  search_no_confident_match.json
│   ├── search_needs_clarification.json  search_semantic_unavailable.json
│   ├── track_detail.json  track_detail_no_audio.json  neighbors.json
│   ├── feedback_refined.json  feedback_rejected.json
│   ├── map_points_page1.json  map_points_page2.json  map_unavailable.json
│   └── error_*.json
├── handlers.ts                # MSW request handlers keyed by scenario
├── scenarios.ts               # named scenarios: "happy", "degraded-semantic", "map-down", "slow-network", "errors"
└── browser.ts / server.ts     # MSW setup for dev and tests
```

- Fixtures validate against the live schema in backend API tests — they cannot drift silently.
- `VITE_API_MODE=mock` runs the dev server entirely on MSW; scenario selectable via query param (`?scenario=map-down`).
- Large synthetic map datasets (10k points) are generated by a script in `mocks/`, never committed if large.

If the UI needs a new state, add a fixture + scenario (functional-owned files) in a small contract task — don't hand-craft JSON inside a story.

## 2. Workbench

Storybook (default) or Ladle — decided at UI intake. Rules:
- One story file per view; each state from `ux-states-and-evidence` is a story, fed by fixtures.
- Containers get stories with MSW scenarios (full page with mocked network).
- Theme/atmosphere switcher in the toolbar to prove token-driven theming.
- Stories are excluded from the boundary checker (they may import fixtures).

## 3. Tests

| Level | Tool | What |
|---|---|---|
| hooks (functional) | vitest + `@testing-library/react` `renderHook` + MSW | loading/error/success, cancellation & stale-response protection, session retention, refresh after feedback, map pagination/filters |
| views | vitest + Testing Library | render per state, events emit typed payloads, nulls render as absent, no `fetch` (MSW `onUnhandledRequest: "error"`) |
| formatters / map helpers | vitest | pure functions |
| containers / flows | Playwright against `VITE_API_MODE=mock` | search → plate → feedback → refreshed plate; map select ↔ details sync; degraded scenarios |
| visual regression | Playwright screenshots (or Chromatic) | key stories per theme; updated deliberately |
| accessibility | `@axe-core/playwright` / storybook a11y addon | no serious/critical violations |
| end-to-end real backend | Playwright, optional, `slow` | one smoke flow against `uvicorn` with the 20-track corpus |

## 4. The isolation test (U05 exit)

Prove the visual layer is swappable: create a throwaway branch where `theme/`, `components/`, `pages/` are replaced by a minimal alternative skin (or switch to a radically different theme) and run: hook tests, contract check, boundary check, backend tests — all must pass untouched. Record the result in `docs/ui/isolation-check.md`.

## 5. Commands (wired in P00/P09)

```bash
cd frontend
npm run dev:mock           # UI on mocks
npm run test               # vitest
npm run storybook          # workbench
npm run e2e                # playwright (mock mode)
npm run contract:check     # regenerate types from openapi.json, fail on diff
```
